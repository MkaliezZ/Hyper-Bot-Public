# Hyper Bot Windows x64 本机测试包

解压整个文件夹，双击 `Hyper Bot.exe`。包内包含 Electron、Node 及课件和练习生成所需的便携 Python。关闭对话窗口后可以从托盘重新打开。通过托盘菜单「退出 Hyper Bot」可结束工作区服务。

首次启动创建独立的本机工作区。会话、材料、运行状态和导出通过当前 Hyper Bot 桌面窗口访问。本机服务异常退出后，桌面程序会在原地址重新启动服务。临时启动失败会自动重试。多次失败时可点击原窗口状态条的「重连」，也可从托盘再次打开。需要提前登记模型和领域组件时，可从命令行检查。命令只报告配置状态。

```cmd
resources\node\node.exe resources\app\scripts\doctor.mjs
```

新工作区的「自媒体口播」由固定版 DSH Web Host 调用已获授权的 DeepSeek 模型，并可接入已安装的 Self Media Workbench。升级后的旧会话沿用各自的 Bot 版本。「素材简报」使用已登记的 Hermes ACP。Windows 桌面可在「维护中心 → 本机依赖」为已有的 Self Media Workbench 或 Hermes ACP 选择安装根目录和 Python。程序先核对锁定提交、入口文件与所需模块。配置有效后在原地址重连本机服务，保留原会话和草稿。Windows 桌面端可在「维护中心 → 本机依赖 → DeepSeek 模型凭据」配置、更换或清除当前工作区的 API Key。依赖缺失时，目录显示原因，已有历史仍可打开。点「检查依赖」查看该 Bot 的组件、锁定版本与 Python 检查。修复原路径下的组件后点「重新检查」，可直接继续原会话。组件设置成功后优先使用本工作区登记。在同一设置中可恢复自动查找，由启动环境的 `HYPER_BOT_WORKBENCH_ROOT`、`HYPER_BOT_WORKBENCH_PYTHON`、`HYPER_BOT_HERMES_ROOT` 和 `HYPER_BOT_HERMES_PYTHON` 或本机安装记录提供配置。修改启动环境后从托盘退出并重新打开。模型连通性在发起任务时验证。装配 DSH Web Host 的口播 Bot 时，可选工作台自带口播规则。样例和发起任务都会核对已登记工作台的原件，用户在原会话批准后写入项目。

装配多个 Skill 时，已选规则按实际提交顺序排列，可用上移和下移调整。候选样例验证通过后，在版本卡点「查看样例成果」，可核对简报、口播分镜和逐条引用。本版开始保留成功验证的预览。复验失败会保留失败原因，旧预览会收起。

在会话输入区，点「粘贴文字」，为采访、笔记等原文填写名称，再点「授权并添加」。原文会加入本轮已选材料，可与 TXT、Markdown 文件混用。添加后可从右侧「材料」回看、取消选用或管理授权。

本会话有刚确认保存的稿件时，空白输入区会显示要续改的版次和仍获授权的原材料。可直接描述改动，点击版次可打开来源稿件。点「另起任务」可清除默认来源与带入的材料。已有草稿优先，也可从右侧「版本」选择较早的稿件继续改。

桌面端通过 Windows 加密保存当前工作区的凭据，空闲时保存即生效。已保存的本机凭据优先使用，清除后回到应用启动时的 `DEEPSEEK_API_KEY`。两处均未配置时，依赖模型的任务暂停接收，已保存的草稿和稿件仍可打开。备份只含工作区数据，恢复到新目录后需为新工作区配置凭据。回滚到 dev.29 时沿用该版的启动环境配置，原工作区的密文可在重新升级后继续读取。源码浏览器和命令行仍可通过启动环境配置。

## 续用独立工作台项目

1. 保持独立 Self Media Workbench 服务运行。工作台入口的 `python workbench.py call GET /api/projects` 会登记或确认本机服务。自定义 `SELF_MEDIA_STATE_DIR` 或 `SELF_MEDIA_DATA_DIR` 时，从配置相同环境的终端启动 Hyper Bot。
2. 在「自媒体口播 → 新建会话」点「连接独立工作台」，从对应分组选项目。到右侧「材料 → 从原项目选用」选用文字。要续改现有版本，选用标有「原稿引用」的文字，再点「带入原稿」。首次新增版本也可直接添加本轮授权的 TXT 或 Markdown。
3. 审批卡显示原项目、稿名、续改来源、拟保存版次及本轮拟登记的文字。点「核对分镜」可打开本轮稿，预览标出改动的镜头。返回会话后点「允许本次写入」。版本冲突后先刷新项目。待核对的任务用「只读核对原项目」检查实际材料或分镜回执。

独立工作台保管原项目、材料和已保存稿件。材料撤回清理 Hyper Bot 的会话副本，原项目里的材料与稿件在工作台管理。

## 查找旧会话和稿件

在侧栏「最近会话」点击「全部」，可按 Bot、会话标题或项目搜索。Bot 目录里的「查看会话」会直接筛出该 Bot 的历史。停用的 Bot 仍可从会话记录中筛选。

成果库按项目组织分镜，简报随来源会话组织。打开版本记录可查看同项目的全部版本，进入稿件或点选授权材料会回到它所在的会话。某版材料授权结束后，目录保留版本记录，其他仍有授权的版本可照常打开和导出。

启用同一 Bot 的另一个版本后，可在旧会话点「切换版本续接」。逐份选择已授权材料，点「授权并新建会话」。新会话会选中这些材料，并可回到原会话。口播会话沿用原有项目绑定。发送任务后仍按新会话的 Bot 版本执行，保存分镜需再次审批。

点会话或分镜里的来源标签，会在右侧「材料」定位并高亮对应原文。底栏显示材料名，点「返回第 N 镜」可回到含引用的具体版本和镜头。手机关闭预览后回到打开预览的位置。

## 导出一版成果

在右侧分镜或简报预览点击「导出稿件」保存 Markdown。单独选中旧版本后，点右边的「导出选项」可将那一版的「稿件与来源」存到一个 ZIP，也可以单独保存 JSON。Markdown、来源 JSON、单版成果 ZIP 和停用 Bot 的历史 ZIP 如遇同名文件，都可在重新打开的保存窗口另存或取消。已有文件保留原样，应用在写入前复查授权。

解压后，打开「稿件.md」阅读。每条引文编号在「版本与来源.json」都有对应的镜头或要点、材料 ID、逐字摘录和首个匹配位置。位置以 Hyper Bot 中获授权文本的 UTF-8 字节为准，使用从零开始的起点与半开区间的终点。行号从 1 开始，重复出现时清单记录匹配次数。用清单中的稿件 SHA-256 可核对同包 Markdown。包里保留所引片段，完整原文仍可在授权范围内从会话打开。

## 保存草稿与确认发送

在预览的「版本」页选定旧稿后，点击「继续改稿」。输入框保留已写好的文字和已选材料，并补上该稿所用的材料。合计超过六份时，先去「材料」取消勾选。切换会话会保留各自的草稿、所选材料和续改版本。打开两个窗口编辑同一会话时，如果已有更新，可选择「采用已保存稿」或「保存当前稿」。

服务断线时，未保存的输入暂存在当前窗口。重连后会核对原会话再保存。发送响应丢失时，应用会查询受理回执。若提示「尚未查到受理回执」，点击「重试同一条消息」沿用原请求编号。

## 服务重启后打开原任务

点击「停止任务」后，会话先显示「正在停止」。运行时确认取消后显示「已停止」。未取得原任务的确认时，会话显示「停止未确认」，并将本轮输出隔离。可在「运行回执」查看结论，也可在原会话带回草稿重新发送。已保存的稿件可继续打开，已撤销的写入需要由新任务重新申请。

「正在找回结果」表示 Hyper Bot 正在核对本机的任务记录。完整的简报会回到原会话，找回的分镜先进入预览和一次性审批。顶部的「查看写入审批」从其他页面或会话直达原任务。若写入结果待核对，从侧栏打开「断线核对」，确认项目和任务后点「只读核对原项目」。找到匹配回执后可打开对应稿件。查无匹配回执时保留待核对，同一项目暂停派活。若确认只有材料登记，页面会显示分镜未保存及已登记数量。

## 材料授权

在会话右侧打开「材料」，选中一份文字后点击「管理授权」。时间按本机时区显示，留空表示持续授权。到期和确认撤回均会关闭原文、相关稿件预览与导出，清理本机材料、相关草稿和工作台受控副本。版本号、任务状态与保存回执可查。旧会话和续接会话使用同一授权。在任一会话设定的期限或确认的撤回会作用于相关会话。正在使用该材料的任务会停止，待审批写入失效。已经送达工作台的提交会结算回执，再清理稿件内容。

自己另存的文件、外部模型服务已经收到的请求和早期备份需按各自的保留范围处理。测试包维护工具会拒绝从到期副本恢复，清理完成后可重新备份。早期非限期备份中的授权以备份里的记录为准，恢复前先核对当前授权。

## 装配新的专项 Bot

1. 在「维护中心 → Skill 与 Harness」登记已审核的运行时，选择 Skill 文件夹。根目录放 SKILL.md，最多六份引用 Markdown 可放在 references/ 及其子目录。检查显示的相对路径及使用依据后，确认审阅并导入。适用平铺引用时，可一次选取主文件和同层 Markdown。选择 Skill 的适用成果类型，通用文字可用于口播或简报。
2. 在「装配 Bot」填写配置并选取验证样例。自备样例需提供任务和 UTF-8 文字材料，也可以指定一段必须在成果里出现的原文引用。勾选允许在会话中载入时，该样例会成为用户可选的演练。
3. 保存候选后会打开对应版本卡，执行「验证样例」。口播样例通过结构和引用校验后，会在独立演练项目保存分镜、回读并清理临时项目。看到「工作台回读成功」即可启用候选。旧版留下的口播候选可在同一卡片重新验证。候选回执记录运行时、装配摘要、验证模型及适用的工作台版本。更换候选的验证模型后重新跑样例。更改配置时可用原稳定 ID 创建下一版。

在「Bot 版本」选择「打开装配草稿」或「基于此版装配」，会带入来源版本的配置和稳定 ID。可更换 Skill 与 Harness、选择新的样例，或确认授权后沿用原样例。保存会建立下一候选版，随后可在对应版本卡上验证和启用。新会话采用已启用的版本，旧会话仍可查看所属版本和成果。

每个 Bot 版次会记录所选 Harness 的版本。若本机安装的版本与原绑定有差异，版本卡会同时显示两者。可点「基于此版装配」选择本机可用的 Harness，重新验证并启用候选版。旧会话仍可查看和导出获授权的成果。

在「维护中心 → Skill 与 Harness → Skill 版本」点「撤销」，可先查看受影响的 Bot 版次。确认后这些版次暂停接任务，待审批授权立即失效。正在生成的任务会请求停止，正在验证的候选会中断。工作台已开始的写入按原提交和回执结算。已保存的稿件仍可查看和导出。重新使用时导入已审阅的新 Skill 版本，从原 Bot 创建候选并重新验证。

## 运行回执与账单

打开「维护中心 → 运行回执」，选择任务类型和统计周期。每项回执显示任务号、Bot 版本、状态、重试关联、提供方编号和已报告用量。查看逐轮记录时可回到原会话；任务结束后可登记实际人工处理秒数、关系动用记录编号以及已核对账单的金额和条目编号。未取得的数值留空。导出回执会下载当前筛选范围的 JSON。

输入 token 已包含命中缓存的部分。失败和重试的已报告用量计入同期统计。发生缺报时，对应字段保持空值。升级前缺少统一口径的旧记录仍可逐轮查看。账单金额使用人工核对后登记的值。

## 停用与导出历史成果

打开「维护中心 → Bot 版本」，在要停用的版本上点「停用此版」。该版本暂停接收新会话及任务，待确认的写入授权随即撤销。已经发出的写入按原任务结算，失联时可从「断线核对」查询回执。

1. 点「查看此版会话」，打开该版本的历史记录。卡片显示当前可以导出的成果数量，以及仅保留版本记录的数量。
2. 点「导出历史成果」，在 Windows 文件对话框选择 ZIP 的保存位置和文件名。材料授权会在确认保存后重新检查。若目标已有同名文件，重新选择名称或位置。
3. 解压 ZIP，从「打开成果.md」查阅 Markdown 稿件。「版本与来源.json」记录 Bot 版本、各稿件的前序版本、会话与原项目回执、来源名称、摘要及稿件 SHA-256。

归档覆盖当前仍获授权的成果与引用。另存的 ZIP 由用户管理。撤回授权仍可从原会话的材料页操作。本机的任务与版本状态可回查，独立工作台按其原有规则保管项目。

如需重新用原版本发送任务，在维护中心确认本机依赖可用后点「恢复此版」。已撤销的写入审批须由新任务重新提出。

## 升级、回滚与备份

两版分别解压到各自文件夹。退出旧版托盘应用后备份工作区，再从新版目录启动。两版默认使用同一个工作区 `%LOCALAPPDATA%\HyperBot`。使用独立工作台功能后，如果回滚到 dev.5 或更早版本，请还原启用该功能之前的 Hyper Bot 备份，再选择原工作台查看已保存的独立项目。回滚时复核本机材料授权。使用自备样例后回滚到 dev.6 或更早版本时，使用启用自备样例之前的备份。联动授权工作区需要 dev.23 或更新版本。使用过「切换版本续接」后回滚到 dev.22 或更早版本时，使用首次续接前保存且已核对授权的备份。需要恢复备份时，先还原到一个新目录，再给对应桌面进程设置 `HYPER_BOT_DATA_DIR` 指向该目录。

```cmd
"Hyper Bot 维护.cmd" backup "%LOCALAPPDATA%\HyperBot" "D:\Hyper Bot 备份"
"Hyper Bot 维护.cmd" verify "D:\Hyper Bot 备份"
"Hyper Bot 维护.cmd" restore "D:\Hyper Bot 备份" "D:\Hyper Bot 已恢复"
```

备份包括聊天、材料、成果、事件和 Hyper Bot 管理的工作台项目文件。独立项目的原件沿用 Self Media Workbench 的备份流程。Hyper Bot 备份保留可读内容，请保存在单用户可访问的目录。恢复要求新目录，并逐文件核对摘要。

## 备份留存与工作区退场

确定留存截止时，在备份命令追加 `--retain-until`。截止须为带时区的 ISO 8601 时间，示例日期按本次留存约定填写。

```cmd
"Hyper Bot 维护.cmd" backup "%LOCALAPPDATA%\HyperBot" "D:\Hyper Bot 限期备份" --retain-until "2030-06-30T17:00:00Z"
"Hyper Bot 维护.cmd" verify "D:\Hyper Bot 限期备份"
"Hyper Bot 维护.cmd" purge-expired "D:\Hyper Bot 限期备份"
```

`verify` 会列出截止时间和能否恢复。设置留存期限的备份使用格式 2，由 dev.18 及支持该格式的维护工具读取，到期即拒绝恢复。回滚应用前，如备份仍在留存期，用 dev.18 的维护工具还原到新的目录，再由旧应用打开该目录。常规备份继续使用格式 1。`purge-expired` 预检一份指定备份，输入预检确认码后删除那份已到期备份。

退出工作区前，可先导出需要保留的历史成果，并把保留的备份和导出文件放在工作区目录之外。从托盘退出 Hyper Bot 后，让维护工具核对实际使用的数据目录。自定义 `HYPER_BOT_DATA_DIR` 时，下面的路径换成对应位置。

```cmd
"Hyper Bot 维护.cmd" retire "%LOCALAPPDATA%\HyperBot"
"Hyper Bot 维护.cmd" retire "%LOCALAPPDATA%\HyperBot" --confirm "填入预检返回的完整确认码"
"Hyper Bot 维护.cmd" purge-expired "D:\Hyper Bot 限期备份" --confirm "填入该备份预检返回的完整确认码"
```

`retire` 删除 Hyper Bot 工作区中的数据库、运行副本、桌面缓存和托管工作台项目。预检会显示实际路径、会话、成果和文件总数。确认码绑定预检时的内容，目录变化后须重新核对。独立工作台目录和另存的文件按各自的留存约定处理。若清理中断，根据命令显示的暂存路径核对后，重试同一命令可继续清理原副本。

## 试用边界

当前归档是本机工程验证件。它使用固定的 DSH 文字配置，包含 Electron、Node、保留的 npm 组件及对应的许可索引。「发布候选清单」另列文本使用范围下排除的依赖、已补入的许可原件和仍待核对的组件。「包内文件摘要」可用于复核实际 ZIP 文件。Windows 11 干净环境、正式分发许可、应用签名与用户验收留在各自的发布检查项。

打包使用 Electron 官方 Windows 外壳布局及 Node 官方 x64 归档。[Electron 打包说明](https://www.electronjs.org/docs/latest/tutorial/application-distribution) · [Node 固定版本摘要](https://nodejs.org/download/release/v25.8.1/SHASUMS256.txt)
